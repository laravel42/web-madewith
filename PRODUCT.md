# MadeWithWhat — Product Context

> **Purpose of this document.** This is a knowledge-base / context file for the
> Infobip AI assistant. It describes what MadeWithWhat is, who it serves, what it
> contains, and where its boundaries are, so the assistant can answer visitor
> questions accurately and avoid inventing scope the product does not have.
> It is written to be read by an AI, not rendered as a marketing page.

---

## 1. One-line summary

**MadeWithWhat is a network of "Made with [technology]" showcase galleries — a
curated, daily-updated catalog of the best open-source projects built with 69
popular web technologies, indexed from real GitHub data and ranked by stars.**

- Network hub: **https://madewithwhat.net**
- Per-technology sites: **madewith‹tech›.com** (e.g. `madewithlaravel.com`,
  `madewithnuxt.com`, `madewithreact.com`). One application serves the whole network.
- Tagline in use: *"open-source project galleries for every stack."*

---

## 2. What it is (value proposition)

For each supported technology, MadeWithWhat answers a single question a developer
keeps asking: **"What can I actually build with this, and what have others built?"**

Each technology gets its own gallery of open-source projects — dashboards, UI kits,
e-commerce platforms, CMSs, dev tools, starters, and more — pulled from GitHub,
ranked by popularity (stars), classified into browsable categories, and refreshed
regularly. Alongside the project galleries, the network also curates **video
tutorials** and publishes **editorial articles**.

The value is **discovery and evaluation**: instead of searching GitHub blindly, a
visitor lands on a focused, ranked, categorized view of a single ecosystem.

---

## 3. Who it is for

- **Developers** choosing or learning a framework/stack, looking for real examples,
  starters, libraries, and tools.
- **Teams** evaluating ecosystems (e.g. "is the Nuxt ecosystem mature for commerce?").
- **Open-source maintainers** who want visibility for their project.
- **Learners** looking for high-quality video tutorials on a specific technology.

## 5. What the product contains (content types)

### 5.1 Project galleries (the core)
Each technology page lists its open-source projects. Every project shows:

- **Name & GitHub identity** (`owner/repo`), author, and avatar
- **Stars** (popularity, the primary ranking signal) and **last-updated** date
- **Description** plus two longer auto-generated summaries
- **Category** (e.g. *Docs, DevTools, UI Kit, Dashboard, E-commerce, Blog, Starter*) —
  projects are auto-classified so a gallery can be filtered by what a project *is*
- **Stack / topic tags**, **language breakdown**, **license**, **demo link**, **repo link**
- **`addedAt`** — when the project first entered the catalog (drives "newest" sorting and RSS)

Projects are **discovered from GitHub, not hand-written**, then filtered so each
gallery only contains projects that genuinely belong to that technology (not tools
that merely integrate with it).

### 5.2 Video tutorials
Curated **English-language YouTube tutorials** per technology (`/video/`). Each video
is quality-gated (views, engagement, HD, duration) and relevance-checked so unrelated
content does not leak in. Many videos are enriched with **AI-generated chapters, an SEO
summary, and a full Markdown transcript**. Fields include title, channel, thumbnail,
duration, views, likes, publish date, and a quality score.

### 5.3 Editorial blog
Long-form articles (`/blog/`) generated by the editorial pipeline, with their own index
and detail pages.

### 5.4 AI-crawler context files
Every domain publishes **`llms.txt`** (a curated top-30) and **`llms-full.txt`** (an
exhaustive, category-grouped list of all projects) so AI crawlers and assistants can
ingest the catalog cleanly.

## 6. What visitors can do (key pages & features)

- **Browse a technology gallery** — `‹domain›/` (ranked project grid)
- **Filter by category** — `‹domain›/categories`
- **View a project detail page** — `‹domain›/project/‹slug›`
- **Browse & watch video tutorials** — `/video/`, `/video/‹slug›`
- **Read blog articles** — `/blog/`, `/blog/‹slug›`
- **Subscribe via RSS** — projects feed (sorted by recency / `addedAt`), videos feed,
  and blog feed (`rss.xml`, `/video/rss.xml`, `/blog/rss.xml`)
- **Submit a project** — `‹domain›/submit` (community submissions, human-moderated)
- **Newsletter signup** — `‹domain›/newsletter`
- **Explore the whole network** — the hub at `madewithwhat.net` cards every category & site

## 7. Data: where it comes from and how fresh it is

This matters for trust — the assistant should represent it honestly.

- **Source of truth:** the public **GitHub API**. Projects are real repositories;
  metadata (stars, languages, topics, license, activity) reflects GitHub.
- **Ranking:** primarily by **GitHub stars**.
- **Freshness:** catalogs are **updated regularly ("daily-updated")** via an automated
  discovery + publish pipeline. Each dataset carries a `scrapedAt` timestamp.
- **Curation / quality control:** raw GitHub results are filtered by a shared
  classification engine and cross-domain scrubbing, so a gallery contains projects that
  *belong* to that technology, correctly categorized — not just anything mentioning it.
- **Videos** come from the **YouTube Data API**, quality- and relevance-gated, then
  optionally AI-enriched (tranworkers/utils/chapters/summaries).
- The scraper **only reads GitHub/YouTube metadata**; it never clones or executes
  discovered repositories.

## 8. How it's built (brief technical context)

- **Static site** built with **Astro** + **Tailwind CSS**, deployed on **Cloudflare Pages**.
- **PostgreSQL** is the primary backing store for repository and video metadata;
  generated **JSON snapshots** (`src/data/*.json`) hydrate the static build.
- An **optional Cloudflare Worker** (with D1 + R2 + Cloudflare Access) powers a
  protected **`/admin`** dashboard for submission moderation, per-domain editorial
  overrides, and manual refresh/republish. `/admin` is private and not part of the
  public product.
- SEO-first: sitemap, per-page OpenGraph images, and the `llms.txt` files.

*(The assistant generally does not need to discuss internal build/ops details with
visitors, but this section prevents confidently wrong statements about the stack.)*

## 9. Scope boundaries — what MadeWithWhat is NOT

To keep the assistant from over-promising:

- It is **not a code host or package registry** — it links to GitHub; it does not host,
  run, or distribute code.
- It is **not a paid marketplace** — everything indexed is **open-source**, and browsing
  is free.
- It does **not guarantee completeness** — GitHub search caps discovery, and low-star or
  brand-new repos may not appear yet.
- It does **not vet security or production-readiness** of listed projects — inclusion is
  based on relevance and popularity signals, not an endorsement.
- It **only covers the 69 configured technologies** (Section 4). It is not a general-purpose
  GitHub search across every language or tool.
- Rankings are **star-based**, which reflects popularity, not necessarily quality or fit.
- `/admin` is an **internal, access-controlled** tool, not a visitor feature.

## 10. Answer-ready facts (quick reference for the assistant)

- **What is this site?** A gallery of the best open-source projects built with a given
  technology, sourced from GitHub and ranked by stars, updated daily.
- **How many technologies?** 69, across Frameworks, Frontend, Backend, CMS/CRM,
  Commerce, and AI/LLM.
- **Where does the data come from?** Real GitHub repositories (and YouTube for videos).
- **How often is it updated?** Regularly / daily via an automated pipeline; each catalog
  shows a scrape date.
- **How are projects ranked?** By GitHub stars.
- **Can I submit my project?** Yes — via the **Submit** page on any technology site;
  submissions are human-moderated before appearing.
- **Is it free?** Yes; all listed projects are open-source.
- **Are there tutorials?** Yes — curated, quality-gated YouTube tutorials, many with
  AI-generated chapters and transcripts.
- **Can I follow updates?** Yes — RSS feeds for new projects, videos, and blog posts;
  plus a newsletter signup.
- **Which technology do I want?** Point them to the matching `madewith‹tech›.com`, or the
  hub `madewithwhat.net` to browse the whole network.
